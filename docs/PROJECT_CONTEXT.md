# 项目上下文与不可变边界

## 当前目标

在 2026-09-04 前交付可运行 Demo 和演示视频，证明以下闭环真实存在：母版建立、目标照诊断、受约束编辑计划、用户确认、外部图片编辑 API 调用、修后复测、停止或重规划。

## 产品定义

产品帮助用户建立自己的 `Reference Profile`，并让单张照片或一组照片分别接近该标准。它不做人脸库、他人搜索、身份认证、自动发布或通用生成式重绘。

## 当前技术冻结

| 层 | 当前选择 | 边界 |
|---|---|---|
| UI | Streamlit | 先交付本地可运行 Demo |
| 状态 | Python 状态机 | 先不引入 LangGraph |
| 数据 | SQLite + JSONL trace | 不做多租户或线上数据库 |
| 视觉 | MediaPipe + OpenCV（后续检查点） | 工具计算特征与质量门 |
| 执行 | 腾讯云 BeautifyPic（后续 API Gate） | 仅授权后端调用 |
| LLM | 可替换 Adapter（后续检查点） | 只输出结构化 IntentFrame/解释 |
| RAG | Provider Card metadata retrieval | 不参与评分或参数计算 |

## 安全与证据边界

- 原图默认不进入 LLM；只允许本地/临时后端处理；
- 外部图片修改必须二次确认；
- 每个工具结果、错误、参数与版本写入 trace；
- 当前项目只能称为可运行原型和方向性 smoke test，不能称为生产上线、准确率、A/B 结果或用户增长；
- 没有授权的照片、腾讯密钥、API 响应图片和个人日志不得进入版本控制。

## 当前开发节奏

每个检查点只做一个完整可验证的能力。完成后必须：更新 `DEVELOPMENT_PROGRESS.md`、记录需要用户决策的事项、运行验证、保留下一步入口。
