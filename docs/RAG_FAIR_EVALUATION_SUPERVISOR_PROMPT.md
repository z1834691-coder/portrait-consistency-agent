# RAG 公平评测与过程监督考官 Prompt（v0.1）

> 这份 Prompt 是本轮工程任务的执行规范。它不是让模型自由发挥的提示词，而是给独立过程监督程序、评测运行器和产品负责人共同使用的“考试规则”。

## 背景

多轮 RAG 优化后，V3/V4 的低分长期混合了几种不同问题：系统有没有听懂自然语言、有没有生成结构化检索请求、检索器有没有找到真实知识、证据之间的关系有没有标对，以及知识库本身有没有覆盖对应规则。旧运行器还把上游投影出来的路由和证据别名合进最终结果，导致分数不能公平解释。

## 本轮目标

<span style="color:#C00000"><strong>把自然语言理解与真实知识检索拆成两条评测轨道；确保同一批 V3/V4 题目每一道都经过统一的 RAG 流程；建立一个独立的过程监督考官，先检查考试是否完整、是否泄露或作弊，再允许后续质量评分。</strong></span>

## 产品负责人已确认的规则

<span style="color:#C00000"><strong>1. 同时覆盖工具能力、权限、隐私、生命周期、过期、冲突和提示注入；不要只测“能不能找到一个工具”。</strong></span>

<span style="color:#C00000"><strong>2. 由产品负责人做人工金标准审核，并增加一名独立盲审 Judge；当前先把过程监督做成确定性考官，LLM Judge 只在过程门通过后作为辅助，不可替代金标准。</strong></span>

<span style="color:#C00000"><strong>3. 保留历史 fixed Precision 口径，同时增加不受稀疏 Gold 条数误导的诊断口径。诊断结果达到三分之一以上可视为“已有一定效果”，达到三分之二以上可视为“较强”，但这两个带只用于解释和迭代，不替换既定项目质量 Gate。</strong></span>

<span style="color:#C00000"><strong>4. 当前知识库规模先不扩张；用现有 V3/V4 题目和现有审核知识做公平流程改造，不再通过增加题目掩盖流程缺口。</strong></span>

<span style="color:#C00000"><strong>5. V3/V4 必须先完成过程完整性检查且确认没有答案、路由标签或证据标签泄露，才能解冻验证；历史快照如果不完整，只能保留为历史证据，不能被“重解释”为通过。</strong></span>

## 两条评测轨道

### 轨道 A：自然语言理解

输入是没有答案的用户问题。系统可以在内存中把问题整理成结构化查询，但不得把答案、Gold 标签或评测路由塞进输出。此轨道只评估：

- 是否生成了结构化查询；
- 任务阶段、部位、工具范围、出站约束等槽位是否明确；
- 不确定时是否显式降级，而不是假装听懂。

“编译失败”可以作为真实失败记录，但不能因此跳过轨道 B。它必须交给一个中性的结构化查询继续走 RAG，并在结果中明确标为“理解未知、继续检索仅为过程完整性保障”。

### 轨道 B：结构化查询到真实知识

输入只能是经过合同校验的 `RagQuery`。最终路由和证据只能来自真实 P0-A/P0-B 检索结果及其 Trace，不能来自上游投影、题目标签、答案键或人工后处理。此轨道评估：

- 实际召回了哪些审核过的知识块；
- 这些知识块排在什么位置；
- 哪些是直接依据、参考信息或冲突信息；
- 检索不到时是否返回“不知道/基线降级”，而不是编造。

## 过程监督考官的检查顺序

对每一道题执行以下检查；任何一项不通过，该题不得进入质量评分：

```text
确认输入题目清单无重复、无缺失
→ 确认没有读取答案、标注、照片、人脸向量或密钥
→ 确认只在内存中保留原问题，并只留下问题哈希
→ 确认自然语言理解结果有明确状态（structured / unknown_fallback）
→ 确认无论理解是否成功，都创建一个合同合法的 RagQuery
→ 确认每一道题都有 query_contract、检索过程和 route Trace
→ 确认最终 prediction 的 route/evidence 只来自 retrieval_result
→ 确认 prediction 证据都能在实际召回/采用证据中找到
→ 确认没有 projection/evidence_aliases/Gold 字段注入结果
→ 确认没有网络、LLM、图片 Provider 等副作用
→ 确认留下 finalized Trace
→ 全部通过后才允许连接独立 Gold 做质量评分
```

## 不得发生的行为

- 不得读取 V3/V4 私有答案来帮助编译器猜题；
- 不得把 `route_override`、`evidence_aliases`、Gold route/evidence 或 case-specific 规则写进最终 Prediction；
- 不得因为题目没有被编译就跳过真实检索；
- 不得把“过程门通过”说成“内容答对”；
- 不得把旧快照的 FAIL 通过改名、换分母或补写 Trace 来伪造为 PASS；
- 不得让 RAG 直接调用图片工具、授予权限或改变 active baseline。

## 必须交付的证据

1. 每个数据集一份 answerless 过程报告：题目数、编译成功数、未知降级数、完整检索 Trace 数、失败数；
2. 一份独立过程监督报告：PASS/FAIL、逐题（仅用哈希或序号）失败代码、答案键/外部调用/注入检查；
3. 旧 V3/V4 快照的历史审计：不能修改旧结果，只能说明它为什么不能解锁；
4. 封存不含原题和答案的脱敏 predictions/Trace 运行包，供过程门通过后按哈希连接 Gold，避免重新跑题；
5. 只有过程门通过后，才生成“可进入下一步 Gold 连接”的状态，不在过程审计中偷算质量分；
6. JSON、HTML、测试和文档中的状态必须一致，且明确 `proposal-only` 与“尚未产品化”的边界。

## 成功标准

过程监督成功不等于 RAG 质量成功。只有同时满足“过程门通过、独立 Gold 未被泄露、两条轨道分别评分、公开回归和安全门不回退、独立 Holdout 质量达到冻结门槛”时，才可讨论 RAG promotion。若过程门失败，必须先修复评测流程，不得继续调检索参数。
