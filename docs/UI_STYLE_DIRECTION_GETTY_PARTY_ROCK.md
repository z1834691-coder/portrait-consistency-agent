# 母版人像一致性 Agent｜视觉风格方向说明

> 版本：`STYLE-DIRECTION-v1.0`
> 状态：<span style="color:#C00000">候选探索，不冻结最终视觉方向</span>
> 适用：E01「入口」与 E02「Agent 对话」两张关键帧、HTML/SVG 可编辑源、后续 Frontend UI 原型

## 1. 这份文档解决什么问题

当前产品的业务逻辑已经收敛为一个简单的 Agent 主链：上传照片，用自然语言表达目标，Agent 自动完成可安全完成的检查与规划，在唯一的外部图片处理边界请求一次授权，然后把结果和可核实的变化告诉用户。

这份文档只定义这条主链应该长什么样。它不改变 `ReferenceProfile`、`PhotoQualityResult`、`IntentFrame`、`EditPlan`、`ProviderRun`、`VerificationResult`、内容安全、隐私、授权、结果保留或 RAG advisory 的既有合同。三套方向都是视觉候选，每套固定制作两张图：E01 入口和 E02 Agent 对话；在产品负责人选定前，任何方向都不能被写成正式实现规范。

## 2. 参考抽象：从 Getty Tracing Art 学到什么

Getty 的 `Tracing Art` 不是把资料堆成普通仪表盘，而是让用户沿着一条清晰的叙事路径，追踪对象从诞生、流转到当下的关系。页面把时间线、人物、地点、机构和作品之间的关联组织成可以逐步探索的视觉结构，并把复杂的数据留在叙事之后。参考页面：[Getty Tracing Art](https://www.getty.edu/tracingart)。

本产品不复制 Getty 的摄影、品牌或页面资产，只抽象以下设计语法：

1. **先给路径，再给数据。** 用户先看到“我现在要做什么、下一步是什么”，再按需展开差异、依据与执行事实。
2. **用轨迹组织复杂关系。** 母版、当前照片、差异、决策、结果是同一条可读的对齐路径，而不是互不相关的卡片。
3. **编辑式留白。** 温暖的纸张色、黑色细线、清晰的版式和有节制的密度承担高级感，装饰不抢任务。
4. **关系比指标更重要。** 视觉上优先表现“当前照片如何向母版靠拢、哪里改变、为什么停下”，不制造虚假的总分、雷达图或 KPI 仪表盘。
5. **多媒体作为证据。** 图片、线条、文字和状态点可以混合，但每种材料都必须服务于一个可核实的任务事实。
6. **滚动/对话有节奏。** 体验按“到达 → 定位 → 上传 → 理解 → 揭晓”的节拍推进；不要让用户先学习一套后台工具。

## 3. 视觉命题

**博物馆档案感 × Silicon Valley 产品的冷静效率 × Party Rock 的灵动色彩。**

这不是黑色赛博界面，也不是传统后台仪表盘。左侧导航像一条安静、稳定的黑色书脊；中间和右侧是可呼吸的米白工作纸；紫色用柔性框、胶囊、轨迹和重点面建立品牌记忆；荧光绿只在对齐轴、活跃节点、处理中状态和轻微运动中出现，让页面有动感但不喧闹。

## 4. 已知视觉约束

### 4.1 色彩与面积

使用 Tweakcn `Party Rock` 的原始 token，不做明暗、饱和度、对比度或色相调整：

| Token | 值 | 在候选方向中的职责 |
|---|---|---|
| 米白 `ivory` | `#F2F1E6` | 中央与右侧的主要背景、阅读面、输入面、照片占位 |
| 紫色 `purple` | `#A855F7` | 关键操作、柔性框、轨迹、激活状态 |
| 淡紫 `lilac` | `#C084FC` | 紫色框的柔和填充、标签和次级高光 |
| 墨黑 `ink` | `#121212` | 文字、规则线、柔性黑框、图标和高对比结构 |
| 黑 `black` | `#000000` | 仅最左侧全局导航的底色；不得成为中间/右侧的大面积背景 |
| 荧光绿 `acid` | `#36FF9B` | 少量活动节点、对齐游标、成功/进行中语义与动感点缀 |
| 珊瑚 `coral` | `#FF4D4D` | 错误、停止和警示；不与紫色同时争夺主 CTA |

新的候选必须同时满足：

- 最左侧导航栏是唯一的黑色大面积区域；中央和右侧主画布保持米白；
- 紫色通过柔和圆角框、圆角标签、轴线和局部面形成连续节奏，而不是紫黑渐变或暗流背景；
- 荧光绿只占很小面积，承担“正在移动/已对齐/当前焦点”的语义；
- 不使用紫色叠加黑色阴影的整块背景，不使用霓虹发光网格，不复制 Party Rock 参考图的具体内容。

### 4.2 形状、边框和材质

- 组件优先使用 `18–28px` 的柔和圆角；圆角是为了减轻界面，不是为了把所有内容做成漂浮卡片。
- 以黑色细线或低对比黑色柔性框隔开内容；黑框可以有轻微厚度，但不使用夸张硬投影。
- 允许少量“丝丝的方框”包住短标题、当前对象或关系节点，形成编辑感；文字与框之间留足呼吸空间。
- 图片框和输入框用米白/白色内面、黑色边界与紫色焦点组合；不要用玻璃拟态、强渐变或厚重阴影。
- 有机轨迹、细线、节点和不完全闭合的框可以表达 provenance/对齐过程；它们必须对齐到真实模块，不得只是装饰。

### 4.3 排版和文案

- 正式界面字体固定为苹方：`PingFang SC`, fallback `Noto Sans SC`, `Microsoft YaHei`。
- 标题短、动词先行：`建立母版`、`开始对齐`、`上传当前照片`、`查看差异`。
- E01 只需让用户知道“上传/开始说”；E02 只需让用户知道“Agent 正在做什么/下一步是否需要我”。
- 每条 Agent 消息最多两到三行：先结论，再最小必要理由；技术字段、原始 Trace 和隐藏思维链退到用户主动打开的“为什么/执行记录摘要”。
- 不放英文 slogan、夸张承诺、未经校准的百分比、计划 A/B/C 或重复提示。

## 5. 两张关键帧的共同结构

### E01｜入口 `/align`

固定表达：

1. 黑色左侧导航：品牌、`对齐`、`母版`、`记录`；当前项用紫色柔性圆角框或紫色短线标识。
2. 米白主画布：当前项目/母版上下文、一个主标题、一个当前照片上传动作和一个 Agent 文字入口。
3. 中央关系线：母版 → 当前照片的轻量轨迹；可用紫色线配一个荧光绿活动点。
4. 左侧标签：`人像一致性项目`、`建立模板`、`模板库`、`新建对象` 等文字使用短标签和少量紫色柔性框，不形成工具栏墙。

### E02｜Agent 对话 `/align/:session`

固定表达：

1. 左侧黑色导航与米白项目上下文保持不变，用户永远知道自己在哪个任务。
2. 中央米白对齐工作区展示母版/当前照片占位、差异摘要、结果揭晓或等待状态；用轨迹和黑色柔性框把它们串成一条线。
3. 右侧米白 Agent 对话区使用黑色细框或圆角边界；消息短而连续，输入框始终在底部。
4. 外部处理授权只在对话中出现一次明确 Sheet；内容安全、质量、同人和 RAG 检查作为后台状态简短告知，不做额外按钮。
5. 结果、反馈和停止都在同一对话里完成，不跳转独立报告页。

## 6. 三个视觉探索方向

<span style="color:#C00000">A/B/C 是前一轮用于建立视觉语言的历史探索，继续保留用于回溯和混合参考；当前最新的精细化执行候选是第 11 节的 Getty × Thread Track 1。未完成负责人评审前，任何方向都不视为最终实现。</span>

### A｜Archive Ribbon「档案游线」

**定位：**最接近 Party Rock 参考图，也是三套中最具“品牌标签”的方向。黑色左导航像档案册书脊，米白画布保持安静，紫色以一条宽窄变化的游线连接母版和当前照片；荧光绿是游线上的当前游标。

**E01 构图与文案：**

- 左侧导航 96px；其余画布米白。
- 上方是 `人像一致性项目` 和紫色圆角标签 `建立模板` / `模板库` / `新建对象`。
- 中部用两个大而轻的黑色柔性框承载 `母版` 与 `当前照片`，中间一条紫色轨迹连接，空状态节点使用荧光绿小点。
- 主标题：`建立母版`；说明：`上传一张你认可的本人照片。`
- 输入入口：`告诉我想保留什么……`；次级文字动作：`已有母版，开始对齐`。

**E02 构图与文案：**

- 中央为 `母版 / 当前照片 / 差异` 的档案游线；右侧米白对话框用黑色细框压住边界。
- 消息示例：`把这张向母版靠拢，保留妆面。`、`收到。我会保留妆面，只处理可可靠测量的脸型和眼睛。`
- 授权与结果作为同一条消息流里的柔性块，不做独立页面。

**质量栏：**结构清晰、色彩有记忆点、手机降级容易；注意不要让紫色轨迹变成装饰线，也不要让标签超过 4 个。

### B｜Soft Index「柔性索引」

**定位：**最接近 Silicon Valley 产品工作台。它减少图形叙事，强化对象索引和对话效率；黑框像编辑器中的柔性分隔，紫色只在当前对象、主输入和重要节点出现。

**E01 构图与文案：**

- 黑色导航 + 米白上下文栏 + 米白主画布，三者通过细黑线而不是深色底切开。
- 顶部用一个黑色细框包住当前对象：`未建立母版`；旁边是紫色胶囊 `建立模板`。
- 中部是一个大上传框，框内只写 `上传母版照片`；下方为短输入 `直接告诉我目标`。
- 右下角用荧光绿小型活动光标表示 Agent 已待命。

**E02 构图与文案：**

- 中央是三段柔性索引：`当前照片` → `差异摘要` → `结果`；每段只显示一句结论。
- 右侧对话区使用米白底、黑色圆角框和紫色用户消息块；Agent 消息保持黑字米白面。
- 状态示例：`我先确认这张照片适不适合比较。`、`现在需要你确认这一次外部处理。`

**质量栏：**效率和可读性最好；注意不要过度像 SaaS 后台，不要让所有区块都变成同尺寸卡片。

### C｜Open Provenance「开放谱系」

**定位：**最接近 Getty 的关系与时间线语法。页面更像一张开放的档案纸：用户沿着母版 → 当前照片 → 决策 → 结果的横向谱系阅读，聊天是路径中的旁白，而不是一个孤立侧栏。

**E01 构图与文案：**

- 左侧黑色导航最窄，米白画布拥有最多留白。
- 顶部短标题 `开始对齐`，标题周围用不完全闭合的黑色方框；副文案只保留 `先上传一张你认可的本人照片。`
- 横向轴线串起 `母版` 和 `当前照片` 两个空节点，紫色节点是长期标准，荧光绿节点表示当前等待上传。
- `建立模板`、`模板库`、`新建对象` 作为轴线上方的紫色柔性标签出现。

**E02 构图与文案：**

- 横向谱系变成 `母版` → `这次照片` → `我会怎么处理` → `结果` 四个叙事节点。
- 右侧/底部是一块米白对话面，黑色线框把 Agent 的消息嵌入谱系；用户消息使用紫色轻填充。
- 关键消息：`照片已检查。下一步会发送给已列明的处理方。`、`结果已返回，我正在确认变化是否朝目标移动。`

**质量栏：**最有编辑和研究气质；注意时间线不能抢走上传和输入的主任务，宽屏缩小时要变为纵向轨迹。

## 7. 选择与验收方法

这三套不是排名，也不是质量结论，而是三种可以被用户直接选择的视觉方向。评审时只回答以下问题：

| 维度 | 需要观察的事实 |
|---|---|
| 第一眼理解 | 5 秒内是否知道下一步是上传照片或说一句话 |
| Agent 感 | 是否像在和一个可靠助手协作，而不是填写后台表单 |
| 视觉气质 | 是否同时具备柔和、艺术、编辑感和 Silicon Valley 的克制 |
| 色彩秩序 | 黑色是否只在左导航/结构出现；米白是否承载阅读；紫色是否灵动但不压迫；荧光绿是否只做动感信号 |
| 信息关系 | 母版、当前、差异、决策和结果是否被一条路径串起来 |
| 文案负担 | 是否没有重复说明、英语 slogan、技术字段或虚假承诺 |
| 可编辑性 | HTML/SVG 的文字、颜色、边框、节点和输入区是否能直接微调 |

评审结论应写成 `选择 A/B/C` 或 `保留 A 的结构 + B 的对话密度 + C 的轨迹`，再进入下一次产品确认。选择前的所有文档和资产都标记为“候选探索”。

## 8. 可编辑交付边界

- `candidate-review.html`：无依赖的候选评审页，可切换 3 套方向和 E01/E02，并填写评审记录；评审页本身不是原生设计编辑器。
- 每套方向的 E01/E02 SVG：按 `nav`、`context`、`workspace`、`agent`、`trajectory`、`copy` 分组，可直接导入 Figma 后取消编组继续编辑。
- Image 2 PNG：用于材质、比例和气质判断；不是精确中文排版源。每张 PNG 保留同名 prompt sidecar 和 `impeccable:prompt` 元数据。
- 不声称生成原生 `.fig`、云端 Figma 文件、真实用户照片结果或 Streamlit 已实现页面。

## 9. 反模式清单

1. 中间/右侧出现大面积黑底，或紫色与黑色组成暗影渐变。
2. 将每一个后台工具、复测步骤、参数和 Trace 都做成可见卡片。
3. 同一套视觉里同时使用多个主 CTA、Plan A/B/C、独立报告页和重复确认按钮。
4. 把荧光绿当大面积底色，把紫色当发光特效，或让颜色替代文字状态。
5. 使用长标题、无业务意义的英文 slogan、虚假的完成百分比或未经验证的“变美/一致”承诺。
6. 直接复制参考图的品牌名、摄影、图表数据或页面资产。
