## 1. 黄金标杆拆解：学什么，不学什么

### 1.1 用户提供的三栏 Agent 参考图

参考图的可迁移设计语法是“稳定导航 + 当前任务 + 连续线程”，而不是复制具体品牌或内容：

1. **左栏是方向感。** 左侧导航拥有稳定宽度、明确的图标—文字组合和当前项高亮；用户始终知道自己在哪个工作空间。
2. **中央是任务主舞台。** 中央区先给当前对象和任务，再给内容流；标题、对象、动作和结果共享一个视觉轴线。
3. **右栏是自然语言线程。** 右侧线程不是独立报告，而是 Agent 的连续旁白。消息短、间距大、输入框固定在底部。
4. **顶部 chrome 很轻。** 顶部只放工作区名称、返回/关闭、必要的上下文动作；不放营销 slogan、重复标题或后台指标。
5. **柔和而不软弱。** 细边框、浅阴影、轻微圆角和米白表面让界面像可长期使用的工作台；黑色只负责导航和结构。
6. **信息密度有节奏。** 中央可有一块内容密度较高的任务区，边缘和输入区保持大留白，避免每一寸空间都被卡片填满。

不复制：品牌 Logo、原始文案、头像、emoji、截图中的真实人物、频道体系、商业数据、第三方水印或页面资产。

### 1.2 Getty `Tracing Art`

Getty 的页面把艺术品的社会生命呈现为一条可追踪的关系路径：对象、人物、地点、时间和证据逐步出现。我们只抽象以下设计原则：[Getty Tracing Art](https://www.getty.edu/tracingart)。

- **先路径，后细节。** 首屏先让用户知道“现在要做什么、下一步是什么”，深层事实按需展开。
- **关系线替代卡片墙。** 母版、当前照片、可测量差异、决策和结果由一条对齐轨迹串联，轨迹必须对应真实模块。
- **章节化节奏。** 入口是“到达”；上传是“定位”；Agent 回复是“旁白”；结果是“揭晓”。每章只强调一个视觉动作。
- **混合媒介作为证据。** 图片、线条、文字、标签、节点可以混合，但每个材料都要回答“它证明了什么”。
- **编辑式留白。** 温暖纸面、黑色细线、节制的字号和不完全闭合的框制造高级感，而不是靠发光、渐变或 3D 阴影。
- **滚动/动效推动理解。** 动画用来说明关系变化和焦点移动，不用来制造“AI 很聪明”的幻觉。

不复制：Getty 的艺术品图片、机构 Logo、真实人物姓名、历史数据、网页动画代码、内容顺序或版权声明以外的页面资产。

### 1.3 `ui-ux-pro-max` 的可迁移建议

已检索并持久化项目级设计系统：[design-system/portrait-consistency-agent/MASTER.md](../design-system/portrait-consistency-agent/MASTER.md)。其中“AI-Native UI、minimal chrome、自然语言输入、spacious density、progressive disclosure、reduced motion、可见 focus”适合作为交互质量参考；它自动生成的紫色/粉色主题、Space Grotesk/DM Sans 与本产品已冻结的 Party Rock + 苹方冲突，因此<strong>不采用其颜色和字体</strong>。图标域检索没有得到可靠匹配，本 Track 回退到单一线性 SVG 图标族（Lucide 风格），不使用 emoji。

## 2. 视觉命题与反模式

### 2.1 视觉命题

**“一张可呼吸的档案纸，承载一个有判断力的 Agent。”**

它要同时拥有：

- 海外产品的克制：少 chrome、清楚的层级、单一主动作；
- 艺术项目的张力：K00 的公共领域艺术照片墙、轨迹和框线有节奏；E01/E02 保持纯米白留白；
- 工作台的可靠：每个状态都有文字事实，动效不伪造进度，用户随时能继续说话；
- C 端的柔和：圆角、米白表面、低压迫密度和自然语言优先。

### 2.2 明确禁止

1. 中央/右侧大面积黑底、紫黑暗影、霓虹网格、玻璃拟态或赛博发光。
2. 传统后台的 KPI 卡片、雷达图、百分比总分、假进度、工具调用日志和工程 Trace。
3. 多个竞争主 CTA、Plan A/B/C、独立诊断报告页、重复确认按钮。
4. 把超现实图片当作可识别的人像或“变美”证明；不得出现真实用户脸、真实结果、身份线索或品牌 Logo。
5. 大段英文 slogan、故意难读的艺术字、正文小于 14px、灰字压在米白上、只靠颜色表达状态。
6. 用 hover 才能发现的关键动作、无键盘替代的拖动、焦点被固定输入栏遮挡、横向滚动的移动端布局。

## 3. 冻结色彩、字体与材质职责

### 3.1 Party Rock 原始 token

| Token | 值 | 视觉职责 | 禁止用途 |
|---|---|---|---|
| `ivory` | `#F2F1E6` | 中央/右侧主画布、阅读面、输入面、图片占位 | 不做脏旧滤镜或大面积渐变 |
| `purple` | `#A855F7` | 当前动作、焦点框、轨迹、用户消息、主 CTA | 不做发光特效或全屏背景 |
| `lilac` | `#C084FC` | 柔性标签、轻填充、关系节点、次级高光 | 不与黑色叠成暗影 |
| `ink` | `#121212` | 正文、标题、细线、图标、结构框 | 不扩展为中间/右侧主背景 |
| `black` | `#000000` | 最左侧导航书脊 | 不出现在中央大面积画布 |
| `acid` | `#36FF9B` | 活动节点、当前焦点、处理中/已对齐的小信号 | 不做大面积面板或主 CTA |
| `coral` | `#FF4D4D` | 错误、停止、不可继续 | 不与紫色争夺正常路径焦点 |

面积是**层级目标而非业务合同**：左侧黑色导航约占桌面宽度的 18–22%；中央/右侧连续米白；紫色以多个柔性局部面、路径和焦点形成明显节奏；荧光绿只保留给少量状态节点。方向评审通过后再用截图复核，不擅自改 token。

### 3.2 字体系统

```css
:root {
  --font-ui: "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif;
  --font-display: "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif;
}
```

| 层级 | 建议字号/行高 | 字重 | 示例 |
|---|---:|---:|---|
| 页面标题 | 32–40px / 1.15 | 600–700 | `开始对齐` |
| 区域标题 | 20–24px / 1.25 | 600 | `当前照片`、`Agent` |
| 正文 | 16px / 1.55 | 400 | `先上传一张你认可的本人照片。` |
| 状态/标签 | 13–14px / 1.4 | 500–600 | `母版已确认` |
| 辅助说明 | 12–13px / 1.45 | 400 | `结果仅在本轮可见` |

标题使用 `text-wrap: balance`，不强行插入不可换行空格；正文单行控制在 60–75 个中文字符以内，移动端不低于 16px。英文只用于必要的产品术语或开发标识，不用于 slogan。

### 3.3 线条、圆角和阴影

- 结构线：`1px` `ink`，必要时 `1.5px`；关键框线最多 `2px`。
- 圆角：输入/消息 `18–24px`；大区块 `24–32px`；胶囊使用 `999px`。
- 阴影：只允许极轻的实体层次 `0 3px 0 rgba(18,18,18,.14)` 或 `0 10px 30px rgba(18,18,18,.06)`；不使用紫黑投影、内发光或模糊光晕。
- 黑色柔性框可以稍厚，但必须配合米白内面和充足留白，不把所有元素做成漂浮卡片。

## 4. 桌面版网格与页面壳

### 4.1 1440×900 首屏基准

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│  黑色导航 240px  │  项目/任务中央工作区 760px       │  Agent 线程 360px       │
│                  │  顶部轻上下文栏 + 内容舞台         │  消息流 + composer      │
└─────────────────────────────────────────────────────────────────────────────┘
```

- 外层安全内边距：上下 `20px`，左右 `20px`；主列间距 `16px`。
- 左栏固定 `240px`，背景纯黑；中央和右栏背景均为 `ivory`。
- 中央列宽度允许 `minmax(560px, 1fr)`；右线程 `320–380px`，不因消息增长挤压中央。
- 三栏之间用 `ink` 的低对比分隔线，不使用深色面板切割。
- 右线程输入框固定在自身底部，内容区使用 `padding-bottom` 预留空间，避免遮住焦点。
- 图像和超现实素材必须声明 `width/height` 或 `aspect-ratio`，避免加载时布局跳动。

### 4.2 1280×800 降级

- 左栏压缩至 `216–224px`，右线程保持不低于 `320px`；中央主舞台缩小但不裁剪输入框。
- 中央的辅助说明折叠为一条短句；关系轨迹由横向变为折线，不删除关键状态。
- 右线程只保留最近的关键消息，历史消息在同一线程内滚动，不新开报告页。

### 4.3 1024px 以下与移动端

- 左侧导航变为可展开 drawer；主界面默认只显示中央任务区。
- Agent 线程变为从右侧/底部打开的 sheet，打开和关闭都有明确按钮与 Esc/返回路径。
- 图片和轨迹纵向排列；禁止页面级横向滚动。
- 断点至少验证 `375 / 414 / 768 / 1024 / 1280 / 1440`；保持 `viewport` 元标签和浏览器缩放能力。

## 5. 模块级视觉规格

### 5.1 左侧全局导航 `PrimaryNav`

- 纯黑书脊：`#000000`；不使用渐变、纹理或大面积紫色阴影。
- 顶部：24×24 线性对齐图标 + 产品短名 `对齐`；不放英文 slogan。
- 一级项最多三项：`对齐`、`母版`、`记录`；`设置`/`帮助`置于底部次级区。
- 当前项：紫色柔性圆角框或紫色短线 + 白字；不可只用颜色表示，需同时有 `aria-current="page"` 和文字权重变化。
- 每项视觉点击/触摸区域不小于 `44×44px`，图标基准 `20–24px`，笔画保持 `1.5–2px`。
- 不使用 emoji；图标来自同一套 SVG 线性图标。

### 5.2 项目上下文栏 `ProjectContext`

- 背景米白，与中央工作区连续；通过一条低对比黑线与导航分隔。
- 第一行显示 `人像一致性项目`，第二行显示短状态，例如 `母版已确认`、`等待第一张照片`。
- `建立模板`、`模板库`、`新建对象` 使用少量紫色柔性胶囊；最多同时出现三个，不形成工具栏墙。
- 任何 Profile 版本、哈希、原始 Provider 字段只进入第二层“为什么/执行记录摘要”。

### 5.3 中央任务舞台 `AlignmentStage`

- 背景连续米白；中央是唯一的任务视觉重心，不使用传统 dashboard 卡片墙。
- 入口状态：上方短标题 + 一句解释；中部一个主上传动作；下方一个自然语言入口。
- 对话状态：母版/当前照片占位、可测量差异摘要、关系轨迹或结果揭晓，全部围绕同一条轴线。
- 照片占位框使用米白内面 + 黑色细边；紫色只在当前焦点/选中状态出现；不放真实人像示意。
- 轨迹节点必须映射真实状态：`母版 → 当前照片 → 检查 → 结果`；节点旁配短文本，不能只留抽象图形。

### 5.4 Agent 线程 `AgentThread`

- 右栏米白面板，黑色细框或低对比分隔线；不使用黑色聊天背景。
- 用户消息右对齐、紫色轻填充；Agent 消息左对齐、米白面 + 黑字；系统事实使用短的黑框事实块。
- 每条 Agent 消息最多两到三行：先结论，再最小必要理由；不展示隐藏思维链、逐步工具日志或假进度。
- 外部处理授权只以一次有界 sheet/消息出现，文案必须含“这一次/当前照片/只尝试一次”等作用域。
- composer 始终可见：可输入自然语言、上传入口或必要的取消/停止；发送按钮用线性箭头图标并有可访问名称。

## 6. 首页 `/align` 精细化稿（E01）

### 6.1 信息顺序

1. **定位：**左栏当前项为 `对齐`，项目上下文显示 `人像一致性项目`。
2. **命名：**中央标题只用 `开始对齐` 或 `建立母版`。

4. **动作：**一个主上传框 `上传母版照片`；已有母版显示文字入口 `已有母版，开始对齐`。
5. **Agent 入口：**composer 占据中央下方视觉重心，placeholder `直接告诉我想保留什么……`。

### 6.2 1440×900 建议排版

- 中央工作区顶部 `40px` 放短上下文标记 `对齐 / 入口`，右侧不放多余 CTA。
- 标题位于中央列 `x=280–720`、`y=96–160` 的首个视觉阅读区；最大宽度约 `12ch`。
- 上传主模块位于 `y=220–520`，宽 `min(640px, 74%)`；左侧保留不可识别的中性**矢量**占位，右侧是动作文字。
- composer 位于中央列下方 `y=590–680`，高度 `80–96px`；发送按钮视觉尺寸 `44px`，可点击区域至少 `48px`。
- E01/E02 不放置栅格图片；K00 的照片墙只位于封面下半部，不能抢过短标题和进入动作。
- 轨迹从上传模块的底部或侧边延伸至 composer 附近，只出现一个紫色活动节点和一到两个荧光绿小节点。

## 7. Agent 对话 `/align/:session` 精细化稿（E02）

### 7.1 信息顺序

1. 左栏保持不变，当前项仍为 `对齐`。
2. 项目上下文显示 `母版已确认`、`当前目标：保留妆面` 等轻量事实。

## 8. 活动素材边界与页面动效

### 8.1 E01/E02 素材决定

产品负责人已明确移除上一版三张 Image 2 环境素材。当前 E01 `/align` 与 E02 `/align/:session` 使用**纯 Party Rock 米白背景**，不加载环境图、纹理、暗流或新插画；这样上传动作、对齐轨迹和 Agent 对话成为唯一视觉重心。`orbit-paper`、`folded-window`、`ink-garden` 及其 prompt 仅保留在 `design/visual-tracks/getty-thread-party-rock/archive/ambient-assets-v1/`，不再被活动 HTML/SVG 引用。

K00 封面是唯一的素材例外：它使用 `cover/artwork/` 中 10 张从 Wikimedia Commons 下载、已在 `SOURCES.md` 登记的历史公共领域艺术作品缩略图；这些图只负责封面文化质感，不参与人像识别、质量判断、Provider 调用或结果解释。为降低现代超现实主义版权风险，本轮使用 Bosch、Arcimboldo、Goya 等“超现实先声”或异想构图，不直接使用仍受保护的 Dalí、Magritte。

硬约束：E01/E02 无栅格素材；K00 不使用真实用户照片、Image 2 生成名画、文字水印或未登记的外部链接。所有 K00 `<img>` 必须有 `width/height`、准确 `alt`、`loading` 策略与来源记录；Figma SVG 只使用相对链接，设计师可替换图片图层。

### 8.2 素材层级

```text
L0  ivory 画布
L1  黑色结构线与关系轨迹（任务语义）
L2  标题、上传框、composer（交互焦点）
L3  Agent 状态/授权 sheet（必要时出现）
K0  K00 封面：紫色主场 → 黑色顶部书脊 → 艺术照片墙（封面专属）
```

E01/E02 的 L0–L3 只使用实体色和矢量几何，关键文字与输入框不使用图片作为背景。K00 的 K0 层使用 `aspect-ratio`、`object-fit: cover`、首屏两张 `loading="eager"`、其余 `loading="lazy"`，并预留 CLS 空间；生产前可转换为 WebP/AVIF，但必须保留 JPG/PNG 回退与来源。

### 8.3 首页动效时间线

| 阶段 | 动作 | 时长/曲线 | 用户意义 |
|---|---|---|---|
| 进入 | 标题、上传框、composer 依次淡入并上移 8–12px | 320ms / `power1.out`，stagger 50ms | 建立阅读顺序 |
| 轨迹 | 紫色路径从母版节点绘制到当前节点 | 900ms / `power2.out` | 表达关系出现 |
| 活动点 | 荧光绿节点一次呼吸 | 1.6s / `sine.inOut`，最多 2 次 | 表达 Agent 待命/当前焦点 |
| 上传后 | 入口上传框变为当前照片占位，composer 保持空间位置 | 280ms / `power1.out` | 保持空间连续性 |
| 对话进入 | E01 的 composer 位置共享到 E02 线程底部 | 360ms / shared-element | 让用户感到进入同一任务，而非跳页 |
| K00 邻近 | 指针/键盘聚焦的艺术卡片向上移动，其他卡片保持原位 | 240ms / `cubic-bezier(.22,.8,.24,1)` | 让照片墙对人的靠近做出回应 |

动效规则：只动 1–2 个关键元素；只用 `transform/opacity`；不动画化 `width/height/top/left`；动画可被点击/键盘立即打断；标签、焦点和正文不做视差。没有真实异步结果时，绝不使用百分比、假加载条或“完成”动画替代事实。

### 8.4 Reduced motion 与动效控制

- `prefers-reduced-motion: reduce`：轨迹直接显示最终状态、禁止循环呼吸和照片卡片抬升；保留文字、焦点环和节点状态。
- 页面提供一个可见的 `暂停动效`/`播放动效` 控制，按钮有 `aria-pressed`；暂停时 K00 照片卡片保持静止，但仍可通过键盘聚焦和点击查看标签。
- K00 不自动轮播、不替换图片；邻近抬升必须同时有 hover、focus 和触控/点击可用的静态反馈，不得把关键入口藏在 hover 后。

## 9. 图标与微交互

### 9.1 图标原则

- 统一使用 Lucide 风格线性 SVG；基准 `24×24`，小图标 `18–20px`，stroke `1.5–2px`，圆角端点。
- 推荐映射：对齐 `ScanLine/AlignCenter`、母版 `CircleUserRound`、当前照片 `Image`、上传 `Upload`、线程 `MessageCircle`、检查 `LoaderCircle`、成功 `Check`、错误 `TriangleAlert`、停止 `CircleStop`、授权 `ShieldCheck`、结果 `Columns2`、展开 `ChevronDown`。
- 图标旁已有文字时标记 `aria-hidden="true"`；图标独立承担动作时必须有可访问名称、pressed/expanded 状态和键盘操作。
- 不使用 emoji、混合填充图标或同一层级的不同笔画风格。

### 9.2 控件状态

| 状态 | 视觉 | 反馈 |
|---|---|---|
| idle | 米白内面 + 黑细边 | 默认可操作 |
| hover | 边框转紫或轻微背景变化 | 150–200ms，不改变布局尺寸 |
| focus | 2–3px coral/ink 外环，offset 2px | 键盘可见，不被线程 composer 遮挡 |
| pressed | 轻微 `scale(.98)` 或实体阴影回落 | 80–150ms 内发生 |
| disabled | 透明度 `.45` + `aria-disabled/disabled` | 不显示悬停假 affordance |
| error | coral 图标 + 原因 + 恢复动作 | 不只靠红色，不把错误藏在 toast |

## 10. 页面行为与真实状态映射

视觉稿只展示“对用户有用的事实”，底层状态继续以现有合同为准：

| 产品事实 | 用户看到的方式 | 不显示 |
|---|---|---|
| 质量/同人/安全后台检查 | 一条 Agent 状态消息或事实块 | 工具名、原始响应、内部分数 |
| 需要澄清 | 一条短问题，最多三个快捷回复 | 多步问卷、参数面板 |
| 外部处理授权 | 对话内一次有界 sheet | 前台内容安全按钮、永久授权 |
| Provider 失败 | 说明是否已调用、失败原因和下一步 | “再试一次”绕过新确认 |
| 结果返回 | 前后对比 + 结构化趋势 + 继续表达 | “变美”、虚假相似度或接受概率 |
| 用户点踩/停止 | 同一线程显示已停止及恢复路径 | 自动续跑、隐形重试 |
| Trace/依据 | 用户主动打开第二层摘要 | 隐藏思维链、全量 JSON、密钥/向量 |

## 11. 可访问性、响应式与性能验收

### 11.1 可访问性

- 正文/控件文字对其背景至少 `4.5:1`；大字至少 `3:1`；米白上的主文字优先使用 `#121212`，不要使用低对比灰。
- 所有输入都有可见 label 或紧邻说明；错误文本通过 `aria-describedby` 关联；动态状态使用单一、简短的 `aria-live="polite"`。
- 键盘顺序严格遵循左栏 → 项目上下文 → 中央任务 → 右线程 → composer；路由切换后焦点移动到主标题或 `main`。
- Modal/sheet 可 Esc 关闭、可返回、焦点陷阱可恢复；固定 composer 不遮住焦点。
- 颜色不是唯一状态通道；荧光绿节点同时有文字/图标说明。

### 11.2 性能

- E01/E02 不加载栅格素材；K00 只 eager-load 首屏两张艺术卡，其余卡片 lazy-load，所有图片预留尺寸，目标 CLS `<0.1`。
- CSS 动效每帧只改 transform/opacity；主线程单帧目标 `<16ms`；页面不可见时暂停照片墙邻近反馈。
- 字体使用 `font-display: swap`；不预加载无用字体；K00 艺术缩略图保持约 900px 长边，避免把原始馆藏大图直接送进页面。
- 流式 Agent 文案逐段呈现，但不让打字动画阻塞输入；用户可立即滚动、复制或提交下一句。
