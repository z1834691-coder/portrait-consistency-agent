# RAG 深度优化与公平验证 Prompt（v0.1）

> 用途：作为本项目后续 RAG 优化、评测、失败归因和是否建立新 Holdout 的统一执行指令。它不是授权书，也不会自动把候选改成现役产品规则。RAG 仍然只能向 Agent、状态机和权限策略提议证据。

## 1. 角色与最终目标

你是本项目的 RAG 评测与优化负责人，同时承担独立过程监督职责。你的目标不是把某个分数调高，而是让系统在**没有见过的新表达**上，真实、稳定、可解释地完成：

```text
理解用户问题
→ 形成合法查询
→ 找到真实知识条目
→ 区分直接依据/参考信息/冲突信息
→ 给出受限路由建议
→ 不越过权限、安全、预算和 Provider 边界
```

最终目标是：在独立新 Holdout 上，质量指标达到可接受的 70%—80% 区间，同时不牺牲安全、隐私、成本、延迟和用户任务完成度。70%—80% 只是产品化讨论的参考区间，不是允许用来掩盖单项硬失败的平均分。

## 2. 当前已知事实（必须先读，不得改写）

1. V3/V4 已有无答案过程重放，过程门通过；旧 V4 快照仍是历史无效快照。
2. 当前知识库规模有限，只有已审核 Provider/Policy 资料；索引同步不等于知识覆盖充分。
3. V4 低分首先暴露自然语言到结构化查询的入口问题，其次才可能是召回、排序或证据关系问题。
4. 早期候选曾出现“只改写 Prediction、没有改变真实检索”的 no-op；以后必须记录 `changed_prediction_count` 和触达的实际层。
5. V3/V4 解冻后的高分只能用于诊断，不能当作新的泛化成绩。
6. RAG 当前 `proposal-only`，不得生成图片参数、授予图片出站、扩大 Provider 白名单或直接调用图片工具。

## 3. 不可违反的公平性规则

### 3.1 数据分层

```text
开发集（可反复看答案）
→ 用于定位失败、设计候选

验证集（每轮只在候选冻结后看一次）
→ 用于比较候选，不用于反复补规则

独立 Holdout（答案封存）
→ 只做一次无答案运行，再做一次受限聚合评分

真实用户数据
→ 单独作为产品效果证据，不与离线 Gold 分数混写
```

同一份验证集反复使用会逐渐“磨损”，独立 Holdout 一旦用于调参就不再是独立测试。每次运行都必须保存代码版本、知识版本、Prompt/策略版本、数据版本和运行时间；旧报告只能追加，不能覆盖。

### 3.2 独立过程监督

过程监督考官与被测 RAG 分开运行，只检查：

- 题目是否全部执行；
- 每题是否都有合法查询、检索和 Trace；
- 预测是否来自真实检索结果；
- 是否读取答案、原题、照片、人脸向量或密钥；
- 是否发生网络、LLM 或 Provider 副作用；
- 是否把 Gold、题目标签、projection 或 route override 注入预测。

过程考官不判断内容答案是否正确。过程门通过后，才允许连接 Gold；过程门失败时，质量分数必须锁定。

### 3.3 防泄露与防过拟合

- Holdout 答案键和逐题 Gold 保存在工作区外，由产品负责人控制。
- 运行包只允许保留不可逆哈希、序号和脱敏事实；不写原题、答案、标签或私有路径。
- 规则不得按具体 Holdout ID 写特例。
- 任何候选必须先通过开发集和公开回归，再运行独立 Holdout；同一 Holdout 不允许试错式重复运行。
- 若候选只提升验证集、不提升新 Holdout，结论是过拟合，不得 promotion。

## 4. 评测拆成两条轨道

### 轨道 A：自然语言理解

输入是用户原话，评估系统是否正确识别：任务类型、动作/信息目的、工具或 Provider 范围、允许出站、隐私/生命周期约束、冲突/注入信号和缺失槽位。现有 V3/V4 Gold 只能先提供“路由代理指标”；真正完整的槽位 Gold 需要单独补标。

### 轨道 B：真实知识检索

输入是已经验证的 `RagQuery`，评估真实知识块的召回、排序、证据关系和路由。预测只能使用实际召回的 chunk/reference，禁止把上游 projection、标签或答案别名写进去。

两条轨道必须分别报分，不得把“没听懂问题”伪装成“检索没找到”，也不得把“规则投影命中”伪装成“知识库召回命中”。

## 5. Goodhart 防护：指标不是目标本身

每轮优化必须同时提交：

1. **主要质量指标**：Route accuracy、Recall@5、MRR、nDCG@5、Evidence relation accuracy、effective/returned Precision；历史 fixed Precision 继续保留但不单独解释。
2. **安全硬门**：越权出站、提示注入放行、冲突直接放行、未知安全事件误判，必须 0 次违规；不能被平均分抵消。
3. **系统约束**：延迟、成本、Trace 完整率、知识新鲜度、空召回率、无依据路由率。
4. **真实任务结果**：用户是否得到正确的“能做/不能做/为什么/下一步”，而不是只返回更多证据。
5. **反例检查**：候选是否通过塞入无关证据、降低阈值、放宽路由、重复调用、按题目写规则或改变分母获得表面高分。

任何一项关键安全或任务完成度下降，都可拒绝候选，即使 Composite 上升。Composite 仅用于看趋势，不能替代 Gate。

## 6. 失败分析与候选迭代协议

每个失败必须先归入可观察层：

```text
输入理解失败
→ 查询槽位缺失/错误
→ 真实召回缺失
→ 排序靠后
→ 证据关系错误
→ 路由决策错误
→ 安全/权限错误
→ 评测口径或数据问题
```

每轮只改变一个主要变量，并写清楚：

- 原因假设；
- 修改了哪个模块；
- 预期改变哪些可观察字段；
- 哪些指标可能变好、哪些风险可能变坏；
- 回滚方法；
- 开发/验证/独立 Holdout 的结果；
- `changed_prediction_count`、Trace 完整率、成本和延迟变化。

如果两轮连续没有改变真实预测，停止在同一层继续打补丁，转向上游或知识覆盖检查。

## 7. 何时建立新的 V5 Holdout

只有在以下条件同时满足时才新建 V5：

1. V3/V4 的公平过程门已通过；
2. 现有答案已完成一次受限 Gold 评分；
3. 已完成逐题失败模式分析，且至少有一个候选在开发/验证集产生真实、可解释的增益；
4. 当前失败主要由表达分布、组合任务或知识覆盖不足造成，而不是评测器未修好；
5. V5 与 V3/V4 做文本去重、语义近重复和概念组合审计；
6. V5 答案键在运行前封存，题目按风险类别分层抽样；
7. V5 一次性无答案运行和过程监督方案已经预注册。

V5 不应只是把 V3/V4 换同义词。建议覆盖：隐含目标、双重任务、否定与范围、过期/冲突、提示注入、权限边界、空召回、长查询、跨语言表达、批量/多脸、未知 Provider 和真实用户常见口语。每个类别都要有开发、挑战和隐藏样本，隐藏样本的答案不能被用于规则编写。

## 8. “训练”在本项目中的准确含义

当前没有在训练一个新的大模型。可做的训练/优化分三层：

1. **规则与知识优化**：改写同义词、Policy Card、查询编译和证据关系，是最适合当前小样本的方式。
2. **检索器实验**：比较 FTS、混合召回、真实本地 embedding、reranker；必须在同一语料和同一候选预算下比较。
3. **模型微调**：只有当积累了足够多、经过审核且不含 Holdout 的真实样本后才考虑；不能把 V3/V4 答案直接当训练数据。

## 9. 行业评测原则（用于设计，不替代本项目 Gold）

- RAG 需要把检索质量和最终回答质量分开观察；常见指标包括 Context Precision、Context Recall、Faithfulness、Answer Relevancy，以及工具调用准确性。
- 真实评测应记录到检索层和端到端层，不能只报一个总分；不同指标服务不同目的。
- 开发集、验证集和独立测试集必须分开；测试集被反复使用会逐渐失去可信度，独立测试应代表真实输入且避免重复样本。
- 评测结果应同时记录安全、成本、延迟和失败类型；安全违规不能被平均分抵消。

## 10. 本 Prompt 的执行顺序

```text
读取当前真相与过程报告
→ 连接已封存运行包与负责人 Gold（只做一次）
→ 输出两条轨道的基线和失败模式
→ 在开发/验证集只改一个变量
→ 公开回归与安全检查
→ 判断是否需要 V5
→ V5 一次性盲测
→ 逐题/聚合失败分析
→ 只保留有真实泛化增益且无安全回退的候选
→ 返回端到端产品化 Gate
```

最终交付必须包含：优化记录、失败模式 SOP、两轨指标、每轮 Trace、反过拟合检查、可视化 Dashboard、候选与基线差异、是否建立 V5 的理由，以及“已实现/已验证/仍未完成”的边界。没有独立新 Holdout 的证据，不得称 RAG 已产品化。

## 11. v0.2 本轮结构化执行指令与真实回执（2026-09-02）

本节是根据产品负责人提出的“先冻结 baseline、逐题分析、过程监督、单变量迭代、必要时建立新 Holdout、用量化证据判断是否泛化”的思考整理出的可执行 Prompt。它补充而不抹去 v0.1 的历史规则；本轮结果以本节和项目当前报告为准。

### 11.1 可直接执行的 Prompt

```text
你是本项目的 RAG 质量负责人和独立过程监督者。先把 V0 的代码版本、知识版本、数据版本、指标口径和运行环境冻结为基线，不把任何答案、标签或 Holdout 题干带入被测系统。

对每一道题必须完整记录：输入哈希 → 自然语言理解状态 → 合法结构化查询 → 真实检索 → 证据集合与关系 → 受限路由建议 → finalized Trace。过程监督者先验证题目没有漏跑、没有答案/标签/照片/向量/密钥泄露、没有 projection 注入或外部副作用；过程门未通过时不得评分。

失败分析必须回答“最早在哪一层出错”：理解、查询、真实召回、排序、证据关系、路由、安全，还是评测口径。每一轮只改一个可解释变量；先在开发集和公开回归验证真实改变，再决定是否保留。候选只能 proposal-only，不能改变 active baseline、Provider 白名单、权限、参数或图片出站。

若当前验证不足以说明泛化，建立与既有题目不重叠的新 Holdout：先封存答案键，只跑一次无答案流程并封存完整 Trace；负责人审核答案后，才做一次独立 Gold join。若没有独立验证证据，不得称 RAG 已产品化。

同时报告 fixed/effective/returned Precision、Recall@5、Hit@5、MRR、nDCG@5、Evidence relation、路由、hard-safety、Trace 完整率、空召回、成本和延迟。不要通过塞无关证据、改变分母、降低安全阈值、按题目写特例或重复试跑来追指标；指标只是质量证据，不是产品目标本身。

最终交付：逐题失败模式、可执行 SOP、候选与 baseline 的差异、公开回归和反过拟合结果、独立 Holdout 过程门、聚合质量分数（若已获负责人授权）、Dashboard，以及已实现/已验证/仍待决策边界。
```

### 11.2 本轮按 Prompt 实际执行的内容

1. **先修真实检索层。**在原有查询编译和证据关系候选之上，加入 `operation_coverage` 候选：当一个问题同时涉及多个操作时，只从已审核、有效的知识条目中为每个请求操作保留代表性证据；它扩大候选池，但不创造知识、不放宽生命周期或权限。
2. **再做回归和逐题诊断。**开发集 28 题、公开回归 52 题均重新运行；每条结果都带候选版本、证据来源、关系和 Trace。当前候选改变开发集 26 条、公开回归 49 条 Prediction 事实；`promotion_decision=not_promoted_proposal_only`。
3. **建立独立 V5。**生成 60 道与 V3/V4 分布和措辞均不重复的题目，覆盖隐含意图、多操作、否定、权限/隐私、生命周期/冲突、注入、未知 Provider、多脸/批量、复测和空召回等类别。答案键在工作区外由负责人保管；无答案运行 `60/60` 完成，过程门 `PASS`，质量评分状态为 `READY_AFTER_SEPARATE_GOLD_JOIN`，尚未读取答案或计算质量分数。
4. **保留可回滚边界。**当前候选没有改变 active baseline，没有调用 LLM、网络、图片 Provider，没有读取照片/向量，也没有把 V5 答案写回代码、知识库或 Prompt。负责人审核 V5 答案键并明确授权后，才能运行独立聚合评分；此前只能把 V5 视为过程已验证、质量待验收。

### 11.3 当前停止条件

候选在公开回归中没有回退，且 operation coverage 对公开 Evidence relation、Recall@5、MRR、nDCG@5 均有小幅真实改善；继续在同一层增加同义词或排序补丁的边际收益已很低。因此本轮不再盲目叠加规则，等待 V5 负责人审核和一次性 Gold join。无论 V5 分数如何，过程门、质量门、RAG `proposal-only` 和产品化结论都必须分开记录。
